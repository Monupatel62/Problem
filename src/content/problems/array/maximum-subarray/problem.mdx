Given a non-empty integer array `nums`, find the largest possible sum of a **contiguous, non-empty subarray** and return that sum. A subarray uses neighboring elements in their original order; you cannot skip a negative value in the middle or reorder the array.

For `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`, the best subarray is `[4, -1, 2, 1]`, with sum 6. It is valid to include a negative number when it helps connect a larger positive total. Conversely, when every value is negative, the answer is the largest single value. For `[-3, -1, -7]`, the result is -1, not zero, because an empty subarray is not allowed.

Checking every start and end pair gives a correct baseline, but it needs O(n²) work even when sums are accumulated efficiently. With up to one hundred thousand values, use a one-pass dynamic-programming observation instead.

At each index, decide whether the best subarray ending there should extend the previous subarray or start fresh with the current number. If the previous running sum is negative, carrying it forward can only make the new total smaller, so discard it. Formally, `current = max(nums[i], current + nums[i])`. Track the largest `current` seen anywhere as `best`.

This is Kadane's algorithm. It handles mixed signs, one element, zeros, and all-negative inputs without special resets to zero. The array is read once and never modified. Return the numeric sum only; the location of the range is not required for this version of the problem. Use ordinary integer arithmetic throughout.
